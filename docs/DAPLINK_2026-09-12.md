Direct benchmarks run separately for 3 seconds; they exclude the normal stream scheduling and UI work. The mixed workload uses the existing `selection-19-split.json` fixture. The 50 MHz mixed run delivered 18.73 S/s for the watch-only fields. It does not claim to reproduce every current user selection.

The mixed-workload clock increase yielded only about 2.5% in this pair of runs, while the contiguous-workload result went down. This does not demonstrate a reliable throughput improvement from increasing the clock beyond 10 MHz. CMSIS-DAP's probe-rs 0.31 implementation returns the requested maximum clock from `set_speed`; its source explicitly says the actual physical clock cannot be determined. Acceptance of 50000 kHz therefore does not establish a 50 MHz waveform. These observations also do not isolate USB transport, probe firmware, target access, and host scheduling as separate bottlenecks.

The earlier ST-Link mixed-workload measurement was about 1003 S/s per Plot channel. That was a different backend revision and requested rate; it provides context, not a controlled probe-only comparison. This Horco run has not reached multi-kS/s acquisition. Raising a requested rate is not evidence of achieving it.

## Software changes and validation

- **Configure Probe / Sampling** updates one selected configuration while preserving its firmware, chip, SVD, flash settings, other fields, and other launch entries. This provides a direct way to replace a stale probe selector.
- Both setup flows expose protocol, requested clock, reset mode, and sampling rate. **Maximum throughput** requests the current 100000 S/s ceiling. The requested clock defaults to 10000 kHz and supports manual higher values. The wizard and schema cap kHz values so conversion to a 32-bit Hz value cannot overflow.
- Foreground acquisition starts with one frame and estimates subsequent batch sizes from measured per-frame cost with a roughly 2 ms budget. Previously, requesting 100000 S/s always requested 200 hardware frames per call. On this probe, the initial pause check took 1512.14 ms. The adaptive run took 19.26 ms. This is not a hard deadline: individual hardware calls can still exceed the estimate, and smaller batches can reduce throughput by repeating call overhead. Short pre-change runs are retained only as diagnostic evidence, not as a controlled throughput comparison.
- Rust workspace tests passed, including the new slow-probe batch-sizing regression. All 32 TypeScript tests and the Mock DAP smoke test passed. The configuration test checks stale-selector replacement, preservation of other settings, and cancellation without saving.
- Version 0.1.6 was packaged and installed into the existing **Cortex Kit** VS Code profile under its legacy `cortex-kit.cortex-kit` extension ID. The installed and tested release backend SHA-256 values match: `c9ed00bda43b16d358e126136e91466abe244a79da53e9c132955495c68b45b3`. Reload the VS Code window and start a new session to load it.
