# Implementation status

This repository is an executable prototype and establishes the vertical architecture. The table separates automated and physical-hardware validation from work that still needs a deeper implementation. The current hardware reference is an STM32H723VGT6 running the existing `wbr_2026` firmware through an ST-Link V2-1; see the [STM32H723 and ST-Link reference run](TESTING.md#stm32h723-and-st-link-reference-run) for the measured results and their limits.

| Area | Current behavior | Validation |
| --- | --- | --- |
| Extension shell | Debug type, configuration provider, Development Host launch, native Variables/Peripherals/Session views, bottom panel, startup activation, Cortex-Debug launch import | TypeScript build and isolated Extension Host smoke test pass |
| Live Watch | Integrated into both Live Plot and Flash & Debug, with independent persistent selection, detailed native value/type/address/access/update-rate rows, structure/array recursive selection, and typed scalar writes that automatically pause, flush, read back, and resume | TypeScript routing/validation tests and Mock DAP byte-level write/readback pass; Live Plot still rejects arbitrary memory writes |
| Mock debugging | Initialize, launch, attach, terminate, pause, continue, reset, three step requests, scopes, mock stack/locals/registers | End-to-end DAP smoke test passes |
| Real probe transport | Enumerates and directly opens probe-rs probes; selects SWD/JTAG speed and target; ST-Link and CMSIS-DAP are supplied by probe-rs | A real STM32H723 session was connected, reset, detached, and reconnected through ST-Link; the CMSIS-DAP/DAPLink path still needs a physical-probe run |
| Breakpoints | Instruction and source breakpoints; source rows resolve through DWARF; a stopped PC maps back to the closest executable row so VS Code can mark the active line; the Session tree exposes a Continue action while halted | A `wbr_2026` breakpoint at `TaskPendulum.cpp:224` stopped at `0x0801e41a`, returned that source row in `stackTrace`, was removed, and resumed |
| Registers and variables | CPU registers come from probe-rs-debug; ELF/DWARF globals expand structures and arrays; at each new stop the extension batch-reads visible scalar fields and registers from expanded/previously-read peripherals, then clears displayed values on continue | The real stopped target refreshed `SysTime.ms` and `DBGMCU_IDC = 0x10016483`; the offline view still indexes 31,513 plottable fields without reading all of them at a stop |
| Memory and disassembly | DAP read/write memory is real; the current disassembly response is a placeholder `nop` sequence | Memory path is exercised by Mock; real disassembly remains |
| Call stack and locals | Mock scopes are available; real DWARF unwind and frame-local expansion are not migrated yet | Pending |
| Stepping | All DAP step commands execute a hardware instruction step | Mock DAP coverage passes; source-aware step-over and step-out and a complete physical stepping check remain |
| SVD | The native tree invokes the Rust parser before or during a session, expands inherited peripherals, arrays, clusters, registers, and fields, hides writes for read-only registers, and decodes field values after a live read | The unit fixture passes; the official STM32H723 SVD produced 117 peripherals, 2,699 registers, and 15,419 fields; the real target returned `DBGMCU_IDC = 0x10016483` through DAP memory read |
| Acquisition | One Worker, urgent command priority, 2 ms acquisition scheduling, merged normal-RAM reads, isolated special/peripheral reads, shared subscriptions, monotonic measured timestamps, actual-rate and drop counters; protected plot mode allows explicit pause/continue and typed writes while blocking flash/reset/step/arbitrary-write/breakpoint operations | Read planner and Mock stream tests pass; real ST-Link plot-only attach sampled a running target, paused and resumed on request, and rejected breakpoint and arbitrary memory-write operations; contiguous addresses are substantially faster than dispersed addresses, while 8 × 5 kS/s was not reached on the reference setup; strict wall-clock burst limiting remains to be enforced |
| Charts | Multiple charts and variables, recursive structure/array selection, shared subscriptions, theme colors, linked cursor, time/FFT/both, connected min/max pixel envelopes, drag reordering, grid/row/column arrangement, layout persistence, socket reconnect, and stale batch rejection | TypeScript selection/reorder and protocol tests pass; the real target delivered changing structure-member samples through the chart binary transport; final visual checks remain manual in the Extension Host |
| Expressions | Rust and TypeScript evaluators support fields/array element names, arithmetic, bitwise operators, comparisons, parentheses, and error gaps | Unit tests pass; pointer dereference and C-style casts remain |
| Flashing | ELF/AXF/OUT, HEX, BIN with inferred NVM base, and UF2; verify and reset options | The existing `wbr_2026` ELF was flashed, verified, and reset successfully through Cortex Kit and ST-Link; the other image formats and DAPLink still need physical runs |
| Discovery | Probes, probe-rs target names, workspace images, SVD files, build tasks, Arm GNU executable, launch-config ELF lookup, and automatic refresh after ELF replacement | The connected ST-Link, firmware ELF, and probe-rs target `STM32H723VG` were used successfully; the existing `wbr_2026` Cortex Kit launch entry was discovered at workspace startup; toolchain discovery remains informational only |
| Packaging | Windows x64 VSIX bundles the release Rust adapter, runtime JavaScript, Webview, icon, and Marketplace README; generated tests and source maps are excluded | `cortex-kit-win32-x64.vsix` generated successfully and its package tree was inspected with `vsce` |

The main remaining product work is real stack and locals, source-aware stepping, bitfield and dynamic-pointer DWARF values, real disassembly, complete CMSIS-Pack discovery, and Rust-side 30-second history replay after a Webview data-socket disconnect. Physical CMSIS-DAP/DAPLink validation and broader flash-format coverage also remain. These items do not change the process split or VS Code API established by the current implementation.
